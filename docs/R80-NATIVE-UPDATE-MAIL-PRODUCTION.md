# R80 — Native in-app update, production mail and Firebase/FCM setup

## 1. What changed in R80

### Android updates stay inside PG Management
The app no longer opens the browser when **Update now** is pressed.

Flow:
1. PG Management checks `https://pg.picsecure.in/app-release.json`.
2. When a newer signed APK exists, the premium update modal opens.
3. **Update now** downloads the APK from inside the Android app.
4. The app verifies the published SHA-256 hash before install.
5. Android may ask once for **Allow from this source / Install unknown apps** for PG Management.
6. PG Management then opens the Android package installer directly for the final Update confirmation.

Android does not allow an ordinary sideloaded app to silently replace itself. The final Android installer confirmation is expected and is a security boundary. No Chrome/browser redirect is used by this flow.

Native patch files are generated by:

```bat
npm run android:native-updater
```

The normal release pipeline runs that automatically:

```bat
npm run release:android
```

## 2. First production Android/FCM setup

The production Android package is:

```text
in.picsecure.pgops
```

In Firebase Console → Project settings → Your apps:
1. Add/select the Android app with package `in.picsecure.pgops`.
2. Download the production `google-services.json`.
3. Save it locally as:

```text
config/firebase/production/google-services.json
```

Do not commit this local production file. R80 copies and validates it during Android release builds.

Check it with:

```bat
npm run firebase:android:prod
```

Native FCM uses `@capacitor/push-notifications`. Owner/Manager token records continue to use the existing `tenants/{tenantId}/pushTokens` collection and the current role filters.

## 3. Web/PWA FCM production key

For browser/PWA push:
1. Firebase Console → Project settings → Cloud Messaging.
2. Under **Web Push certificates**, generate/use the production key pair.
3. Copy the **public VAPID key** into `src/environments/environment.production.ts`:

```ts
vapidKey: 'YOUR_PRODUCTION_PUBLIC_VAPID_KEY'
```

The VAPID public key is client configuration, not a server secret.

## 4. Resident email — production setup

R80/R79 send resident receipt and rent reminder emails from Firebase Functions through Resend.

### Resend
1. Create a Resend account/project.
2. Add `picsecure.in` (or a mail subdomain such as `mail.picsecure.in`) in Resend Domains.
3. Add the exact DNS records shown by Resend to GoDaddy DNS.
4. Wait until Resend reports the domain as verified.
5. Create a **production API key**.

Never put that API key in Angular source, Git, `environment.ts`, or the APK.

Store it in Firebase Secret Manager:

```bat
firebase use production
firebase functions:secrets:set RESEND_API_KEY --project mana-pg
```

Paste the key only when the CLI prompts for it.

Verify metadata without printing the secret:

```bat
firebase functions:secrets:get RESEND_API_KEY --project mana-pg
```

The sender defaults to:

```text
PG Management <noreply@picsecure.in>
```

For a different verified sender, create `functions/.env.mana-pg` locally:

```text
MAIL_FROM=PG Management <noreply@picsecure.in>
```

Then deploy Functions again.

## 5. Production key separation

### Keep in Firebase / Google Secret Manager
- `RESEND_API_KEY` — secret, Functions only.
- Future server-only payment/API credentials — add with `defineSecret()` and Firebase Secret Manager.

### Production client Firebase configuration
These values are intentionally present in the frontend build and are **not secret credentials**:
- Firebase Web API key
- authDomain
- projectId
- appId
- messagingSenderId
- public Web Push VAPID key
- App Check public site key

R80 keeps production client config isolated in:

```text
src/environments/environment.production.ts
```

Angular production builds use this file through `fileReplacements`.

### Native Android Firebase configuration
Keep the production Android Firebase config at:

```text
config/firebase/production/google-services.json
```

It is copied only for native builds.

### Do NOT put these in Firebase frontend config
- Android release keystore/passwords
- Resend API secret
- Cloudflare R2 encryption KEK
- private service-account JSON keys

Cloud Functions deployed inside Firebase use Google-managed credentials, so no downloadable Firebase Admin service-account private key is required by this project.

### R2 secret stays in Cloudflare
`FILE_KEK_B64` belongs to the Cloudflare Worker and should remain a Wrangler secret:

```bat
cd r2-worker
npx wrangler secret put FILE_KEK_B64
```

Do not duplicate that encryption key into Angular or Firebase client config.

## 6. App Check production recommendation

`environment.production.ts` has `appCheckSiteKey`. Configure a production App Check provider/site key, test first, then enable enforcement in Firebase Console. Do not enable enforcement before the production web/PWA/native clients are confirmed healthy.

## 7. Production deploy order

After setting mail + FCM configuration:

```bat
npm install
npm run production:check
npm run build
npm run functions:build
firebase use production
firebase deploy --only firestore:rules,functions,hosting --project mana-pg
npm run r2:deploy
```

`r2:deploy` is needed only when the R2 Worker changed. It is not required for every UI-only release.

For a new Android release/update:

```bat
npm run release:android
```

This builds the signed APK, calculates SHA-256, creates `app-release.json`, places the APK in Hosting, deploys Hosting, and makes the installed app detect the release on launch/resume.

## 8. What a user sees on update

- Update modal inside PG Management.
- Download progress inside the same modal.
- No browser opens.
- First sideload update may open Android's **Install unknown apps** permission screen for PG Management.
- After permission, tap **Install update** again.
- Android's secure package installer appears.
- Tap **Update / Install**.
- Existing Firebase data remains untouched.

The same package ID and the same permanent release signing key must be used for every update.
